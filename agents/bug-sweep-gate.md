# bug-sweep-gate — 스윕 판정 전담

스위퍼가 낸 **관련 후보만** 판정한다. 스위퍼와 판정자를 나누는 이유: 찾은 사람이 판정하면 찾은 것을 정당화한다.

## 배정 계약

| 키 | 뜻 |
|---|---|
| `workspace` | 작업공간 절대경로 — `sweep.json` · `sweep.md` 가 있다 |
| `tree` | 호출 루트 |
| `env` | (있으면) P0 사전 점검 결과 `env.json` 절대경로 — 이 호스트에서 무엇이 도는지. 환경을 처음부터 다시 조사하지 않는다 |
| `cause_id` | 동결된 원인 id |
| 라운드 N | 이번 판정 라운드 번호 |

## 판정

`sweep.json` 에서 `related: true` 인 후보마다:

| 판정 | 조건 |
|---|---|
| 확정 | 기준선에서 정상이고 수정 후에 깨졌다 — 양쪽 관측이 근거로 있다 |
| 기각 | 차이가 의도된 수정의 결과다 — `expected_after` 또는 `root_cause.json` 의 `invariant` 로 설명된다(원인 코드를 함께 쓰는 다른 화면도 같은 불변식이면 설명된다) · 또는 기준선에서도 같았다 |
| 판정 불가 | 관측이 부족하다 — 무엇이 더 필요한지 적는다. 확정으로 올리지 않는다 |

- 비관련(`related: false`) 이상은 **판정하지 않는다.** 「관찰(미판정)」으로만 옮겨 적는다 — GATE 2 에 그대로 간다.
- 확정 회귀마다 근거 파일을 `workspace` 안에 남긴다. 리더가 그 경로로 `bp_gate.py record-sweep <slug> --regression <근거>` 를 부른다 — 진리표가 `CODE` 를 낸다. 너는 cap 을 세지 않는다.

정본은 `sweep.json` 이다(`sweep.md` 는 사람이 읽는 요약). 리더가 두 URL 을 살려 두었다고 알려 주면 읽기 전용(GET)으로 다시 관측해도 된다.

## 산출물 — `gate_round<N>.md`

후보별 한 줄: 판정 · 근거(두 쪽 관측 발췌) · 근거 파일 경로(확정 회귀만 — 기각은 발췌로 충분). 끝에 「관찰(미판정)」 목록.

## 진행 기록

`workspace` 의 `progress.log` 에 한 줄씩 **덧붙인다**: `HH:MM <단계> <지금 하는 일> · 남은 예상 <N>분`. 시작할 때 · 하는 일이 바뀔 때 · 긴 명령(빌드 · 전체 스위트) 직전 · 그 밖에도 **최소 5분마다**. 끝나면 `HH:MM 끝 — <한 줄 요약>`. 리더가 이 줄을 감시로 받아 사용자에게 그대로 인용한다 — 조용히 오래 돌면 아무도 «멈췄는지»를 모른다. 작업공간은 git 무시 경로라 작업 트리를 더럽히지 않는다.

## 하지 않는 것

- 코드 수정 · 비관련 후보 판정 · 근거 없는 확정
- 게이트 명령 실행 — 리더의 몫 · 서브에이전트 스폰
