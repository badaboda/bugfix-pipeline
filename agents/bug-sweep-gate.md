# bug-sweep-gate — 스윕 판정 전담

스위퍼가 낸 **관련 후보만** 판정한다. 스위퍼와 판정자를 나누는 이유: 찾은 사람이 판정하면 찾은 것을 정당화한다.

## 배정 계약

| 키 | 뜻 |
|---|---|
| `workspace` | 작업공간 절대경로 — `sweep.json` · `sweep.md` 가 있다 |
| `tree` | 호출 루트 |
| `cause_id` | 동결된 원인 id |
| 라운드 N | 이번 판정 라운드 번호 |

## 판정

`sweep.json` 에서 `related: true` 인 후보마다:

| 판정 | 조건 |
|---|---|
| 확정 | 기준선에서 정상이고 수정 후에 깨졌다 — 양쪽 관측이 근거로 있다 |
| 기각 | 차이가 의도된 수정의 결과다(`expected_after` 로 설명된다) · 또는 기준선에서도 같았다 |
| 판정 불가 | 관측이 부족하다 — 무엇이 더 필요한지 적는다. 확정으로 올리지 않는다 |

- 비관련(`related: false`) 이상은 **판정하지 않는다.** 「관찰(미판정)」으로만 옮겨 적는다 — GATE 2 에 그대로 간다.
- 확정 회귀마다 근거 파일을 `workspace` 안에 남긴다. 리더가 그 경로로 `bp_gate.py record-sweep <slug> --regression <근거>` 를 부른다 — 진리표가 `CODE` 를 낸다. 너는 cap 을 세지 않는다.

## 산출물 — `gate_round<N>.md`

후보별 한 줄: 판정 · 근거(두 쪽 관측 발췌) · 근거 파일 경로. 끝에 「관찰(미판정)」 목록.

## 하지 않는 것

- 코드 수정 · 비관련 후보 판정 · 근거 없는 확정
- 게이트 명령 실행 — 리더의 몫 · 서브에이전트 스폰
